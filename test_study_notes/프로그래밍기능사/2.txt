1. DMA 기반 데이터 입출력(Direct Memory Access)과 CPU 개입 수준
- DMA는 입출력 장치–메모리 간 데이터 전송을 DMA 컨트롤러가 직접 수행하여, CPU는 전송 시작 설정과 완료 인터럽트 처리 중심으로 관여합니다.
- 장점: CPU가 바이트/워드 단위 전송을 매번 제어하지 않아 CPU 부하 감소, 전송 효율 향상에 유리합니다.
- 비교 관점 정리
  - CPU 직접 제어 방식(프로그램드 I/O 등): CPU가 전송 과정에 지속 개입 → 단순하지만 비효율 가능
  - DMA: 대량/고속 전송에 적합, CPU는 다른 작업 병행 가능
- 실무 포인트: “CPU의 지속적인 개입 없이 메모리로 직접 전송”이라는 문구가 나오면 DMA를 우선 연상합니다.

2. CPU 구성 요소와 데이터 경로: ALU·제어장치·주기억장치의 역할 분담
- CPU 내부 핵심 기능 분리
  - ALU(산술논리연산장치): 덧셈/뺄셈 같은 산술 연산과 AND/OR/비교 같은 논리 연산을 실제 수행
  - 제어장치(CU/CLU): 명령 해독, 제어 신호 생성, 장치 간 동작 순서 조율
  - 주기억장치(Memory): 프로그램과 데이터를 저장, CPU가 가져와 처리한 뒤 결과를 저장
- 정보 이동(데이터 경로) 관점
  - 기본 흐름은 주기억장치 ↔ CPU 내부(연산장치/제어장치) 사이의 이동으로 이해하며, 연산 수행은 ALU 중심으로 일어납니다.
  - 문제에서는 “주기억장치, 제어장치, 연산장치 사이에서 정보가 이동되는 경로” 같은 표현으로 구성요소 간 관계를 묻습니다.
- 오답 포인트
  - Memory Unit/I-O Unit은 각각 저장/입출력 담당이며 연산 수행 주체(ALU)와 구분해야 합니다.

3. 상태 레지스터(플래그)와 프로그램 실행 제어: 조건 분기·순서 제어의 핵심
- 플래그 레지스터(Flag Register)는 ALU 연산 결과에 따라 생성되는 상태 비트(예: Z(Zero), C(Carry), V(Overflow) 등)를 저장합니다.
- 제어장치(CLU/CU)는 플래그 값을 참조하여
  - 조건 분기(예: 결과가 0이면 점프),
  - 조건부 실행,
  - 다음 마이크로동작/명령 수행 흐름
  을 결정하므로, “실행순서 제어”와 연결됩니다.
- PSW(Program Status Word)는 플래그를 포함하는 더 넓은 상태 개념으로 등장할 수 있으나, 문항이 “연산 결과 상태 비트 기반 제어”를 직접 겨냥하면 플래그 레지스터가 정답 축입니다.

4. 주소 지정 방식(Addressing Mode): 간접 주소 지정의 의미와 판별법
- 간접 주소 지정(Indirect Addressing)은 명령어가 가진 주소 필드가 실제 데이터 주소가 아니라 ‘주소가 저장된 위치’를 가리키는 방식입니다.
  - 즉, 지정된 저장위치의 “내용(content)”이 유효주소(EA, Effective Address)가 됩니다.
- 판별 키워드
  - “번지로 지정된 저장위치의 내용이 실제 번지가 된다” → 간접지정
- 비교 관점(혼동 방지)
  - 즉시/직접/상대/절대 등은 주소 필드가 실제 주소이거나(직접/절대) 기준값에 더해 계산되는 형태(상대)인데, 간접은 한 번 더 참조(메모리 참조 추가)가 핵심입니다.

5. 순차논리 회로와 플립플롭 동작: JK 플립플롭의 토글(Toggle) 조건
- JK 플립플롭은 입력(J,K) 조합에 따라 다음 상태가 결정되는 대표적 순차논리 소자입니다.
- 핵심 동작 요약
  - J=0, K=0: 유지(Hold)
  - J=1, K=0: Set(1로)
  - J=0, K=1: Reset(0으로)
  - J=1, K=1: 토글(Toggle) → 출력이 보수로 전환
- 시험 포인트: “보수가 출력”, “토글”이라는 표현은 J=K=1로 연결합니다.

6. 2의 보수(Two’s Complement) 표현: 보수 계산 절차와 의미
- 2의 보수는 음수 표현 및 뺄셈을 덧셈으로 처리하기 위한 대표적 이진 표현 방식입니다.
- 계산 절차(고정)
  - 1의 보수: 비트 반전(0↔1)
  - 2의 보수: 1의 보수에 +1
- 실전 팁
  - 보기 중 “비트 반전 결과에 1을 더한 값”이 있는지 확인
  - 최상위 비트(MSB)는 부호비트로 해석될 수 있으므로, 문제 요구가 “2의 보수로 표현”인지 “2의 보수 값 계산”인지 문장을 정확히 구분합니다.

7. 명령어 사이클(Instruction Cycle) 구성 요소: Fetch·Indirect·Interrupt의 구분
- 명령어 사이클은 CPU가 명령어 1개를 처리하기 위해 거치는 단계들의 집합입니다.
- 대표 구성(시험 빈출)
  - Fetch Cycle: 명령어를 메모리에서 가져옴
  - Indirect Cycle: 간접 주소 지정일 때 유효주소 계산을 위해 추가 메모리 참조 수행
  - Interrupt Cycle: 인터럽트 발생 시 상태 저장 및 ISR로 분기
- 주의 포인트
  - “Branch Cycle”처럼 일반적인 표준 사이클 구성으로 보지 않는 항목이 오답으로 등장할 수 있으므로, 교과서적 기본 3~4단계 구성을 우선 기준으로 잡습니다.

8. 연산 분류와 논리 연산(Logic Operation): AND/ROTATE/COMPLEMENT vs 산술 연산
- 연산은 크게 산술 연산과 논리(비트) 연산으로 구분해 접근합니다.
- 논리적(비트 단위) 연산 예
  - AND: 비트 단위 논리곱
  - COMPLEMENT: 비트 반전
  - ROTATE: 비트 이동/회전(시프트·로테이트 계열은 논리/비트 조작 범주로 자주 분류)
- 산술 연산 예
  - MULTIPLY(곱셈), ADD(덧셈) 등은 값의 산술적 계산이므로 논리 연산과 구분됩니다.

9. 기본 논리 게이트 판별: 진리표로 NAND/NOR/AND/OR 구분
- 진리표 기반 판별의 핵심은 “출력이 0이 되는 경우”를 먼저 잡는 것입니다.
- NAND 게이트 특징
  - AND의 부정: 두 입력이 모두 1일 때만 출력 0, 그 외는 1
- 비교 포인트
  - AND: 둘 다 1일 때만 1
  - OR: 하나라도 1이면 1
  - NOR: OR의 부정(하나라도 1이면 0, 둘 다 0일 때만 1)
- 실전 적용: 진리표에서 (1,1)일 때 출력이 0이면 NAND 가능성이 매우 높습니다.
