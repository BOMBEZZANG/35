여러분, 안녕하세요!  
오늘은 컴퓨터구조에서 시험에도 잘 나오고, 실제로도 “아, 그래서 이런 식으로 돌아가는 거구나” 하고 감이 확 오는 핵심 주제들을 한 번에 쭉 연결해서 강의처럼 풀어볼게요. 내용이 9개로 나뉘어 있지만, 사실 큰 흐름은 하나예요. CPU가 어떻게 일하고, 메모리/입출력과 어떻게 데이터를 주고받고, 그 과정에서 명령어가 어떻게 실행되며, 하드웨어 논리가 어떻게 뒷받침하느냐 이거거든요. 자, 그럼 차근차근 가봅시다.



 1) DMA 기반 데이터 입출력(DMA)과 CPU 개입 수준

자, 먼저 “입출력” 이야기부터 시작해볼게요. 컴퓨터에서 데이터가 이동하는 대표적인 상황이 뭐냐면, 예를 들어 디스크에서 메모리로 파일을 읽어온다, 또는 네트워크로 받은 데이터를 메모리에 쌓는다 이런 상황이죠.

 (1) CPU가 직접 다 하는 방식: 프로그램드 I/O 같은 방식
가장 단순한 방식부터 생각해봅시다.  
CPU가 직접 장치한테 “한 바이트 줘!” 하고 받고, 또 “다음 바이트 줘!” 하고 받고… 이런 식으로 전송 과정에 계속 끼어드는 방식이 있어요.

장점: 구조는 단순해요. CPU가 다 통제하니까요.
단점: 근데 이게 치명적입니다. 데이터가 크면 어떡해요?  
  CPU가 계속 전송만 하느라 바빠요.  
  그러면 정작 중요한 계산이나 다른 작업을 못 하죠.

 (2) DMA: “CPU의 지속적인 개입 없이” 장치↔메모리 전송
여기서 등장하는 게 DMA(Direct Memory Access) 입니다.  
이름 그대로, “메모리에 직접 접근해서 전송한다”는 느낌이죠.

DMA에서는 핵심 주체가 CPU가 아니라 DMA 컨트롤러예요.

CPU는 뭐만 하냐?
  1) 전송 시작 전에 “어디서 어디로 몇 바이트 옮겨!” 같은 설정을 해줍니다.  
     예: 시작 주소, 전송 크기, 방향(장치→메모리 또는 메모리→장치)
  2) 그리고 전송이 끝나면 완료 인터럽트가 오거든요?  
     그럼 CPU는 “아 끝났네” 하고 마무리 처리를 합니다.

즉, CPU는 전송 과정에서 바이트/워드 단위로 매번 관여하지 않아요.  
이게 엄청 큰 차이입니다.

 (3) DMA의 장점 한 줄로 정리하면?
CPU 부하 감소
대량/고속 전송에 효율적
CPU는 그동안 다른 계산 작업을 병행 가능

그리고 실무/시험 포인트!  
문제에서 딱 이런 문구 나오면 바로 떠올리셔야 해요.

> “CPU의 지속적인 개입 없이 메모리로 직접 전송”

이 문장 보이면 거의 반사적으로 DMA를 찍을 수 있어야 합니다.



 2) CPU 구성 요소와 데이터 경로: ALU·제어장치·주기억장치 역할 분담

자, 이제 CPU 내부로 들어가 볼게요. CPU는 크게 “뇌” 같은 존재라고 하잖아요? 근데 뇌도 영역별로 역할이 나뉘듯이, CPU도 핵심 구성요소가 나뉩니다.

 (1) ALU(산술논리연산장치): “계산 담당”
ALU는 말 그대로 연산을 “실제로” 합니다.

산술 연산: 덧셈, 뺄셈
논리 연산: AND, OR, 비교(크다/작다/같다)

여기서 중요한 건, 연산의 주체는 ALU라는 거예요.  
“연산한다”라는 말이 나오면 ALU를 떠올리는 게 기본!

 (2) 제어장치(CU/CLU): “지휘자”
제어장치는 직접 계산을 하기보다는, 일을 시킵니다.

명령어를 해독하고(Instruction Decode)
“이 타이밍에 레지스터로 보내!”
“이 신호를 1로 올려!”
“메모리 읽기 신호 줘!”

이렇게 제어 신호를 만들어서 CPU 내부와 외부 동작을 조율해요.  
그러니까 제어장치는 오케스트라 지휘자라고 생각하면 좋아요.

 (3) 주기억장치(Main Memory): “프로그램과 데이터 저장소”
메모리는 프로그램(명령어)과 데이터를 저장하고 있다가,

CPU가 가져와서 처리하고
처리 결과를 다시 저장하는

이 흐름의 중심 저장소예요.

 (4) 데이터 경로(정보 이동 경로) 관점
시험에서 이런 말이 나올 수 있어요.

> “주기억장치, 제어장치, 연산장치 사이에서 정보가 이동되는 경로”

이건 결국 “데이터가 메모리에서 CPU로 들어오고, ALU에서 연산되고, 제어장치가 흐름을 통제한다” 이 관계를 묻는 거예요.

그리고 오답 포인트!  
Memory Unit(저장)과 I/O Unit(입출력)은 역할이 다르고  
“연산 수행 주체”는 어디까지나 ALU라는 걸 헷갈리면 안 돼요.



 3) 상태 레지스터(플래그)와 실행 제어: 조건 분기·순서 제어의 핵심

자, 여기부터가 진짜 “CPU가 똑똑해지는 지점”이에요.  
우리가 프로그램에서 이런 거 많이 하죠?

if (x == 0) 점프
if (a > b) 다른 루틴 실행

이걸 CPU는 어떻게 할까요? 바로 플래그(Flag) 로 합니다.

 (1) 플래그 레지스터(Flag Register)는 뭐냐?
ALU가 연산을 하면 결과가 나오죠?  
근데 결과 “값” 말고도, 결과의 “상태”가 중요할 때가 많아요.

예:
결과가 0이냐? → Zero 플래그(Z)
자리올림이 발생했냐? → Carry 플래그(C)
오버플로우가 발생했냐? → Overflow 플래그(V)

이런 상태 비트들을 저장하는 곳이 플래그 레지스터입니다.

 (2) 제어장치가 플래그를 보고 “다음 행동”을 정한다
여기가 포인트예요.  
플래그는 저장만 해놓는 게 아니라, 제어장치가 그 값을 참고해서 실행 흐름을 결정합니다.

“Z가 1이면 점프해!”
“C가 1이면 다른 분기 타!”
“결과가 음수면(N 플래그 같은) 다음 명령을 바꿔!”

이런 식으로요.

그래서 문제에서 “실행순서 제어” “조건 분기” 이런 말이 나오면  
플래그 레지스터 ↔ 제어장치 연결을 떠올리면 됩니다.

 (3) PSW(Program Status Word)와의 관계
PSW는 플래그를 포함한 “좀 더 큰 상태 묶음”으로 나오는 경우가 있어요.  
근데 문항이 “ALU 연산 결과 상태 비트 기반 제어”를 정확히 찌르면 정답 축은 플래그 레지스터라고 보시면 됩니다.



 4) 주소 지정 방식: 간접 주소 지정(Indirect Addressing) 판별법

자, 이제 명령어가 “데이터가 어디 있는지”를 어떻게 가리키는지 보겠습니다. 이게 주소 지정 방식(Addressing Mode)이죠.

 (1) 간접 주소 지정이 뭐냐?
간접 주소 지정은 한 마디로:

> 명령어의 주소 필드가 “진짜 데이터 주소”가 아니라  
> “진짜 주소가 들어있는 곳”을 가리킨다.

즉, 한 번 더 거쳐요.

명령어에 적힌 주소 A가 있음
메모리 A로 가서 내용을 읽음 → 그 내용이 실제 주소 EA(유효주소)
그 EA로 가서 진짜 데이터를 읽음/씀

그래서 간접 주소 지정은 메모리 참조가 한 번 더 추가됩니다.  
이게 핵심입니다.

 (2) 시험에서 바로 잡는 키워드
문제에서 이런 표현 나오면 간접 주소 지정이에요:

> “번지로 지정된 저장위치의 내용(content)이 실제 번지가 된다”

여기서 “내용(content)”이 딱 등장하면 거의 확정이라고 보셔도 됩니다.

 (3) 다른 방식과 혼동 방지
직접/절대: 주소 필드가 실제 주소에 가깝다
상대: 기준값(예: PC)에 더해서 계산한다
간접: 주소를 한 번 더 따라간다(추가 참조)



 5) 순차논리 회로와 플립플롭: JK 플립플롭의 토글 조건

자, 이제 하드웨어 쪽으로 조금 내려가 볼게요. CPU나 메모리도 결국 논리회로로 만들어진 거니까요.

 (1) JK 플립플롭이 뭐냐?
플립플롭은 “상태를 저장”하는 대표 소자고, JK 플립플롭은 입력(J, K)에 따라 다음 출력이 정해집니다.

여기서 중요한 건 시험에 거의 공식처럼 나오는 동작표예요.

 (2) JK 동작 4가지 (이건 통째로 기억!)
J=0, K=0 → 유지(Hold) : 그대로
J=1, K=0 → Set : 1로
J=0, K=1 → Reset : 0으로
J=1, K=1 → Toggle(토글) : 출력이 보수로 바뀜(0↔1)

 (3) 시험 포인트
문제에서 “토글”, “보수가 출력된다” 이런 말이 나오면  
바로 J=K=1로 연결하셔야 합니다.



 6) 2의 보수(Two’s Complement): 계산 절차와 의미

자, 이제 이진수에서 음수를 어떻게 표현하는지!  
컴퓨터가 뺄셈을 편하게 처리하려면 음수 표현이 중요하거든요. 그 대표가 2의 보수입니다.

 (1) 2의 보수의 목적: 음수 표현 + 뺄셈을 덧셈으로
예를 들어 A - B를 하고 싶을 때,  
A + (B의 2의 보수)로 계산하면 되니까, 하드웨어 입장에서는 “덧셈기 하나로” 많은 걸 처리할 수 있어요.

 (2) 계산 절차는 무조건 고정
2의 보수 절차는 바뀌지 않습니다. 순서도 고정이에요.

1) 1의 보수: 비트를 반전(0↔1)  
2) 2의 보수: 1의 보수 결과에 +1

예를 들어 8비트에서 00010110이 있다.
1의 보수: 11101001
+1 해서 2의 보수: 11101010

이런 식이죠.

 (3) 실전 팁
보기 중에 이런 문구가 있으면 정답 후보예요.

“비트 반전 결과에 1을 더한 값”

그리고 하나 더. 문제에서
“2의 보수로 표현하라” 인지,
“2의 보수 값을 계산하라” 인지

요구가 다를 수 있어요. 특히 MSB(최상위 비트)가 부호 비트로 해석되는 상황도 있으니까 문장 정확히 읽어야 합니다.



 7) 명령어 사이클: Fetch·Indirect·Interrupt 구분

자, 이제 CPU가 명령어 하나를 처리할 때 거치는 “절차 묶음”을 봅시다. 이게 명령어 사이클(Instruction Cycle) 이죠.

 (1) Fetch Cycle: 명령어를 가져오는 단계
가장 기본은 Fetch입니다.

PC가 가리키는 메모리에서 명령어를 읽어서
IR(Instruction Register) 같은 데에 넣고
PC를 다음으로 증가시키고

이 “가져오기”가 Fetch예요.

 (2) Indirect Cycle: 간접 주소면 유효주소 계산을 위해 추가 메모리 참조
아까 간접 주소 지정 배웠죠?  
간접이면 주소를 한 번 더 따라가야 하니까, 그 추가 단계를 Indirect Cycle이라고 부릅니다.

“간접 주소 지정일 때만” 등장한다는 게 포인트예요.
메모리를 한 번 더 읽어서 EA를 확정하는 단계라고 이해하면 됩니다.

 (3) Interrupt Cycle: 인터럽트 처리 흐름
인터럽트가 발생하면 CPU는 하던 일을 잠깐 멈추고, 인터럽트 서비스 루틴(ISR)으로 가야 하잖아요?

그때 필요한 게 Interrupt Cycle입니다.

현재 상태 저장(예: PC, PSW 등)
ISR로 분기

이 흐름이죠.

 (4) 주의 포인트: Branch Cycle 같은 “그럴듯한 오답”
시험 문제에서 “Branch Cycle” 같은 걸 섞어놓고 고르라고 할 수 있어요.  
물론 분기 자체는 명령어로 하긴 하지만, 보통 교과서적 사이클 구성 요소로는 Fetch / Indirect / Interrupt 같은 기본을 기준으로 잡는 문제가 많습니다.



 8) 연산 분류: 논리 연산(Logic) vs 산술 연산(Arithmetic)

자, 이제 연산 종류를 구분하는 문제! 이거 은근히 함정이 많아요.  
핵심은 “비트 조작이냐, 값의 계산이냐” 입니다.

 (1) 논리(비트) 연산 예시
AND: 비트 단위로 둘 다 1이면 1
COMPLEMENT: 비트 반전(0↔1)
ROTATE: 비트를 밀고(shift) 돌리는(rotate) 동작

여기서 ROTATE 같은 게 애매해 보이는데, 시험에서는 보통 비트 조작으로 묶어서 논리 연산 범주로 분류하는 경우가 많습니다.

 (2) 산술 연산 예시
ADD, SUBTRACT, MULTIPLY 같은 것들  
이건 “값의 크기”를 계산하는 산술이죠.

그래서 문제에서
AND / ROTATE / COMPLEMENT / MULTIPLY
이렇게 나오면, MULTIPLY만 산술 연산이라 튀는 경우가 많습니다.



 9) 기본 논리 게이트 판별: 진리표로 NAND/NOR/AND/OR 구분

마지막은 진리표 문제! 여러분이 진리표를 보면 흔히 “다 적어보고 판단”하려고 하는데, 더 빠른 요령이 있습니다.

 (1) 요령: “출력이 0이 되는 경우”부터 잡아라
게이트 판별은 1이 되는 경우를 보는 것도 좋지만, 특히 NAND/NOR 같은 “부정” 계열은 0이 되는 패턴이 눈에 확 띕니다.

 (2) NAND 특징: AND의 부정
NAND는 이렇게 기억하세요:

AND는 (1,1)일 때만 1
NAND는 그 반대니까  
  (1,1)일 때만 0, 나머지는 1

즉, 진리표에서  
입력이 (1,1)일 때 출력이 0이다?  
그러면 “NAND 가능성이 매우 높다” 이거예요.

 (3) AND / OR / NOR 비교로 마무리 정리
AND: 둘 다 1일 때만 출력 1
OR: 하나라도 1이면 출력 1
NOR: OR의 부정  
  하나라도 1이면 0, 둘 다 0일 때만 1
NAND: AND의 부정  
  둘 다 1일 때만 0

이렇게 대비하면 헷갈릴 일이 확 줄어듭니다.



 마무리 연결 정리 (흐름으로 기억하기)
자, 오늘 배운 걸 흐름으로 한 번 연결해볼게요.

대량 입출력 전송에서는 CPU가 계속 붙잡혀 있으면 비효율 → 그래서 DMA가 등장한다.  
CPU 내부는 계산(ALU), 지휘(제어장치), 저장(메모리)로 나뉘고, 데이터가 그 사이를 오간다.  
ALU 연산 결과는 플래그로 남고, 제어장치는 그 플래그를 보고 분기 같은 실행 순서 제어를 한다.  
명령어가 데이터를 가리키는 방식 중 간접 주소는 “주소를 한 번 더 따라가는 방식”이고, 그래서 명령어 사이클에 Indirect Cycle이 추가될 수 있다.  
이 모든 하드웨어 기반에는 플립플롭(JK 토글 조건 J=K=1), 2의 보수(반전+1), 논리 연산/게이트 판별 같은 디지털 논리가 깔려 있다.
